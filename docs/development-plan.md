读取纪律：

- 禁止全量载入大源码 / 完整历史 / 全文对话；仅**小且整段必须使用**的文件可整读，并注明理由。

- 验收通过**实际调用 / 交付的读取窗口摘要**佐证，主代理审查有无无关全文加载。
- 原则性自动加载 `system` / `AGENTS`，及程序化 `build` / `schema` / `hash` / 完整 JSON 解析，
  **不计**人工全文加载，但不得输出密钥 / 无关内容。

1. **一个有界任务包**：一个执行会话只承接一个可验收、有界任务包，禁止无限追加 / **同一整包层层转发**，完成即结束；不同细分任务新 `task`、不传旧 `task_id`。任务开工前须冻结：目标、允许写范围 / 文件所有权、需求摘要与依赖签名、必须读取的文件 / 章节 / 符号或行窗口、检查命令与验收标准。大任务开工前拆分 phase / checkpoint，**checkpoint 不事后扩充任务边界**。执行者直接完成，规则见 §10。
2. **先搜索后局部读取**：先 `Grep` 定位再 `read offset/limit`，禁止大源码 / 完整历史 / 全文对话 / 沿无关链接递归全量载入。补读须记录疑点与原因；摘要不含秘密。保留既有例外：**小且整段必需的文件可整读并注明原因**；程序化 `build` / `hash` / `schema` / 完整 JSON 解析**不等于**人工全文加载，但不得输出密钥 / 无关内容。
3. **预算与可观测性**：派发前主代理核实所选模型**实际配置**的 context 总上限 `C`、最大输出预留 `O`，另选收尾安全余量 `B`，记录预警与交接阈值及来源；**最大窗口不是会话目标**。主代理授权 GLM 当前 `C=220000` / `O=30000`，采用保守操作预算 `B=30000`，当前输入占用最多 `160000`（`220000-30000-30000`）；预警 `140000`、交接 `160000`。**明确**这些是项目操作策略值，不是模型服务端硬上限，也不是已经触发的实际用量；只在能取得可信"当前完整上下文输入占用"时比较；不得用多轮累计计费 token 相加当占用（缓存命中 token 仍占上下文），不得把 output 上限当实际已输出。其他模型不套 GLM 数字，按各自配置确定预算。
4. **检查时点**：任务派发前、每个预定阶段交付、扩大必要读取范围前、每轮返修前，主代理 / 子代理按运行时**实际可得信息**核对预算与目标。真实当前用量可得时记录来源 / 时点 / 度量含义；**以条 3 的 GLM 示例预算为例**，达 `140k` 预警立即收敛输入、不追加新探索，下一必要操作预估可能超 `160k` 也提前交接；达到 `160k` 在可安全停写边界整理摘要并 `NEEDS_HANDOFF`，不耗到 `220k` 才处理（`140k` / `160k` / `220k` **仅适用当前 GLM 示例**，`220k` 为其配置上限而非统一硬值）。**其他模型沿各自 brief 按条 3 确定的预算与阈值执行，不套用 GLM 的 140k / 160k / 220k**。不假设父代理能在同步 `task` 调用途中实时读数 / 打断；只能使用工具**实际支持**的能力。
5. **不可见指标**：无法取得真实用量时明确记录"**当前上下文用量不可见**"，不伪造 token 数量 / 余量 / 已触发阈值的结论；改用每个有界阶段结束检查 + 可观察异常（重复无进展搜索、遗忘约束 / 错误复述范围、方案混淆、反复无关读取、臆测接口）。发现这些信号立即停止新探索并安全交接。自动 compaction 或模型大窗口**不能**代替任务边界 / 可验证 handoff。
6. **交接**：`NEEDS_HANDOFF` 不是完成、也不是业务 `BLOCKED_DECISION` 批准；先停写，记录目标 / 需求契约版本 / 修改路径与符号 / 已测未测 / 失败尝试 / 阻塞 / 下一步 / 文件归属、读取窗口摘要、预算与当前度量（或不可见）/ 触发原因、会话与逻辑任务累计返修轮次。主代理检查实际文件与交接，旧执行结束后再新会话接力；新上下文只给最小摘要与必要文件片段，不搬整段旧对话，相同文件不能并发写。
7. **返修上限**：仍为**最多 2 轮**，换 session 不清零逻辑累计；超预算 / 两轮不通过时由主代理分析拆分，不能伪装澄清无限堆积。

9. **验收命令分级（T060）**：验收 brief 的检查须分为**必跑** / **条件检查**（写清触发条件）/ **仅引用已有证据**（注明来源），**不写模糊"必要时"让子代理自行决定验收**；验收 brief **不得扩充实施已冻结的验收标准**；缺额外证据由**主代理定位**，不转嫁验收方自行加测。
10. **再次派发分类（T060）**：再次派发前主代理先分类——**原验收标准未达** → **原包有限返修并累积轮数**；同一逻辑任务中**已明确冻结但尚未派发**的独立交付物 → 另开**有界包**，**不得靠换 session 重置预算**；**范围外 / 验收后新发现** → 记**后续任务**，**不因"顺手"自动继续**。
11. **收口与 DoD（T060）**：收口写清**已接受的子交付 / 未完成 / 未测**；**整任务 DoD 未满足不得标 done**；验收**不得变相无限扫描或重新定义通过标准**；发现**关键安全缺陷**按**原标准核验 / 决策处理**，**不以停点掩盖**。

