# 当前开发工作流

本文件只描述**当前生效**的工作流。过去的委派、writer、固定模型顺序、强制新会话、再委派和流程实验已经退出当前规则；需要追溯时使用 Git 历史。

## 1. 设计目标

工作流优先优化实际开发效率，而不是追求流程完整度。

核心目标：
- 小需求尽量在一个主代理会话内完成；
- 子代理只在能明显降低复杂度或提高并行/独立验证价值时使用；
- 控制默认读取量，不让历史 md 成为启动成本；
- 发现新问题不自动扩展成任务链；
- 一次性用户指令不自动沉淀为长期规范。

## 2. Fast Path：默认路径

适用条件：
- 目标清楚；
- 修改局部；
- 不改变业务需求或接口契约；
- 可以用有限代码定位和针对性验证完成。

流程：

```text
理解请求
→ 定位代码/测试
→ 最小修改
→ 针对性验证
→ 汇报结果
```

Fast Path 不要求：
- T-XXX；
- 子代理；
- 独立验收代理；
- 完整任务 brief；
- 上下文预算表；
- 同步 tasks / decisions / verification；
- 读取完整 docs 或历史任务。

只要修改不产生长期需求、契约或交付证据变化，就不要为了“流程完整”写额外 md。

## 3. Complex Path：按复杂度升级

出现以下情况之一才升级：
- 关键需求/契约歧义；
- 跨多个独立模块；
- 可真正并行的独立交付；
- 调查范围大，但结果可压缩成局部上下文；
- 当前主会话出现明显上下文退化；
- 高风险变更需要独立验证。

升级前主代理先做一次成本判断：

```text
子代理带来的上下文隔离/并行/独立性收益
>
新会话建立、重复读取、handoff、回传与再理解成本
```

不满足时仍由主代理直接执行。

## 4. 子代理 Brief

仅在 Complex Path 使用。Brief 保持最小：

- 目标：一个可独立判断成败的交付结果；
- 可写范围：文件/模块/符号；
- 必要事实：已核实的需求或契约；
- 验收方式：必跑检查；
- 不做什么：关键边界。

不要把完整历史、整个 `tasks.md`、旧验证日志或大量 markdown 作为默认上下文。

## 5. 上下文读取策略

读取顺序：
1. 先搜索定位；
2. 读当前代码窗口；
3. 需要业务语义时读对应 requirement / contract 小节；
4. 只有出现具体疑点才查 decisions / verification / Git 历史；
5. 复杂且仍未定位时才考虑 `explore`。

禁止“为了对齐项目”机械读取整个 docs 树。

### Active Context

默认活动上下文：
- `AGENTS.md`
- 当前需求/契约相关片段
- 当前代码与测试
- 必要时的 `docs/tasks.md` 当前状态

Historical Context 默认不进入上下文。

## 6. 问题发现策略

额外发现的问题先分类：

| 分类 | 处理 |
| --- | --- |
| 当前验收必须解决 | 当前任务内修 |
| 相关但不影响当前验收 | follow-up，默认不执行 |
| 关键业务/契约/安全问题 | 暂停受影响范围，重新定界或 BLOCKED_DECISION |

发现问题本身不能触发新子代理、新任务或范围扩张。

## 7. 会话策略

- 主代理是长期调度和默认执行会话。
- 小任务、同一局部需求的定位/修改/验证保持在当前会话。
- 新子代理只服务 Complex Path。
- 不再执行“不同细分任务一律新会话”的规则。
- 只有上下文可靠性下降、真正并行或独立高风险验收时才 handoff。
- 新会话使用最小摘要，不重放完整旧历史。

## 8. 规范沉淀策略

用户指令默认 = 当前任务作用域。

只有明确表达长期意图时，才能修改项目规范。以下内容通常只属于当前任务，不自动长期化：
- “这次直接改”
- “先不要用某个代理”
- “这次只测某项”
- “这个文件先别动”
- 临时模型或工具选择

规则升级必须有清晰长期语义；AI 不自行推断“用户以后都想这样”。

## 9. 验证策略

验证与风险匹配：

- **低风险**：相关 lint/编译局部检查/目标测试；
- **中风险**：相关单测 + 构建/静态检查；
- **高风险**：集成/端到端/独立验证，按需要增加。

主代理核验实际结果后完成任务。独立验收是按风险升级能力，不是固定阶段。

## 10. 文档与历史

- `tasks.md` 只跟踪仍然活跃、阻塞或需要后续人工验收的工作；
- 已完成任务的流水记录依赖 Git 历史，不继续堆在活动任务文件；
- `verification.md` 保留有交付价值的验证，不记录每个微小编辑的流水；
- `decisions.md` 只保存仍有长期影响的重要决定；
- 本文件不登记每一次流程调整的执行 session、模型、返修轮次。

## 11. 当前收口规则

任务结束时只回答：
- 改了什么；
- 实际验证了什么；
- 哪些仍未测；
- 是否有不影响当前验收的 follow-up。

不要因为存在 follow-up 就自动继续执行下一任务。
