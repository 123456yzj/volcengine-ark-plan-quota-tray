## 设计建议（非用户逐项确认）

以下为主代理基于用户原话做的合理设计，**不是用户已逐项确认的结论**：

- **UI 形态**：解释为 Windows 系统托盘（任务栏通知区）常驻图标 + 点击弹出浮窗。
- **数据源**：复用本机 ArkCLI 登录身份查询套餐额度，而非另存凭据。
- **MVP 交互**：托盘菜单提供"退出"；手动刷新；关闭浮窗不退出；第一版按需刷新。
- **CLI 发现顺序**（实现记录）：`ARK_LEFT_CLI`（必须是存在的绝对 `.exe`）→
  PATH 中 `arkcli.exe` → npm shim 目录下
  `node_modules/@volcengine/ark-cli/bin/arkcli-windows-amd64.exe`。
  **仅支持原生 `.exe`**，不通过 PowerShell 托管 `.ps1` shim（避免 shim 孙进程占用
  stdout/stderr 管道使超时无法收敛）；避免硬编码用户路径、不经过未转义 shell。
- **认证闸门**（实现记录）：`auth status` 需退出码 0 且顶层 `logged_in=true`
  才查询额度；非零 / 启动失败 / 缺字段 / 非布尔 / 超时 / 取消分别判定，互不混淆。
- **子进程环境**（实现记录）：设置 `ARKCLI_NO_UPDATE_NOTIFIER=1` 防隐式更新；
  移除 `ARKCLI_CALLER_TYPE` / `ARKCLI_CALLER_NAME` / `ARKCLI_SKILL_NAME`，
  应用正常运行不冒充 AI 调用方。

> 这些属于普通技术 / 交互实现选择。按本项目约定，**普通内部技术事项由主代理在授权内
> 调研决定并记录即可，不要求用户逐项批准**；只有涉及业务含义或验收标准时才升级用户。
>
> **v0.3 授权技术决定（Q-005）**：旧设计建议中的“第一版按需（手动 / 点击时）刷新”
> 与“无跨账号持久化缓存（无磁盘缓存）”已被交互层 v0.3（UX011）**覆盖**为
> “打开零查询 + 启动后台一次 + 每 5 分钟轮询（含隐藏）”与“跨重启本地快照
> （DPAPI / 原子写入 / 仅不可逆 scope 指纹，不存凭据与原始身份 ID）”。
> 详见 Q-005 与 [`requirements/interaction-improvements.md`](requirements/interaction-improvements.md)。
> **业务数据范围不变**；上述为交互 / 技术层覆盖。

## 消息状态与问题状态的区别

- 消息状态只表示送达/回复情况，**不代表同意**。
- 问题状态表示事项是否闭环：`OPEN → DECIDED → CLOSED`。
- `DECIDED` 是已有答案；`CLOSED` 才表示决定落实且验证通过。
- 无回复不得默认批准，不设超时自动通过。

## 决定闭环流程

```
发现问题 → 查依据（无依据则 OPEN + 暂停相关范围）
        → 有权者确认 → 记录结论/依据/确认人/日期/生效版本（DECIDED）
        → 通知受影响代理并确认采用版本 → 落实并验证 → CLOSED
```
