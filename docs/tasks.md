## 什么时候需要任务记录

只有以下情况才建议创建/保留 T-XXX：
- 跨多步、跨模块且无法在一个 Fast Path 中可靠完成；
- 存在 `BLOCKED_DECISION`；
- 需要多个独立交付物或跨会话 handoff；
- 需要长期跟踪的人工/环境验证；
- 用户明确要求任务化管理。

普通小改动使用：

```text
Locate → Edit → Verify → Done
```

不要求写入本文件。

## 状态

复杂任务可使用：

```text
pending → in_progress → done
              ↘ blocked_decision → in_progress
```

- `blocked_decision`：关键业务/契约/验收歧义尚未解决。
- `NEEDS_HANDOFF`：仅表示复杂任务需要换会话继续，不等于 done。
- `done`：冻结的验收标准已经满足；未执行的检查必须显式写成未测。

## 额外问题

开发过程中发现的新问题不得自动变成新任务：

1. 当前验收必须解决 → 当前范围内修复；
2. 不影响当前验收 → follow-up，默认不执行；
3. 关键业务/契约/安全问题 → 重新定界或 `BLOCKED_DECISION`。

## 交接最小信息

只有确实需要 handoff 时记录：
- 当前目标；
- 已修改文件/符号；
- 已验证与未验证；
- 未完成原因；
- 下一步；
- 当前文件写入归属。

不要复制完整对话、完整历史任务或大量无关 md。
