## 产品目标

做一个常驻 Windows 桌面右下角（系统托盘）的轻量小插件：常驻一个托盘图标，
用户点击后在托盘附近弹出浮窗，展示当前身份下火山方舟订阅（Agent Plan / Coding Plan）
的剩余额度、周期与重置时间。用户无需打开控制台或手动敲命令即可确认
“我的方舟套餐还剩多少 / 用了几成 / 几号刷新”。

## 用户与使用场景

- 用户：本机 Windows 用户，已在本机通过 ArkCLI 登录过火山方舟订阅账号。
- 场景：快速确认方舟套餐剩余额度与重置时间。
- 前置：本机存在可用的 ArkCLI 且已登录；未登录 / 未安装时按异常状态提示（见 R003）。

## 范围（In Scope）

- 常驻托盘图标与点击弹出浮窗（R001）。
- 展示当前身份下订阅套餐的**剩余百分比（为主）**、剩余绝对量（若有）、周期与重置时间（R002）。
- 只读查询当前已登录身份的订阅额度。
- 明确的异常与状态展示，失败不伪装成 0（R003）。

## 排除项（Out of Scope）

- 不购买、升级、切换、退订任何套餐或资源包。
- 不切换 profile、不轮换 / 新增 API Key。
- 不含按 Token 计费的账单 / 费用（`usage stats`、`billing`）展示。
- 不含实时预算控制、限流、告警。
- 不查询语音模型（TTS / ASR）用量或额度。

## 需求（编号唯一，沿用 v0.1）

- **R001（托盘常驻与弹出）**：Windows 系统托盘常驻图标，单击后在托盘附近弹出轻量浮窗。
  【设计建议】浮窗定位需考虑工作区、DPI 缩放与多屏，避免弹出到屏幕外。
  **不承诺图标强制可见**：Windows 可能将图标收入“折叠 / 溢出区”（用户个性化设置），
  本插件不保证图标始终直接可见，这是系统行为而非需求违规。
- **R002（剩余额度展示）**：以**剩余百分比为主**展示当前身份订阅的产品、周期桶
  （如 `5h` / `weekly` / `monthly` / `session`）与重置时间（**字段存在时才显示**）。
  当 `percent`（已用百分比）为 25 时，主展示**剩余 75%**，可**辅以**已用 25%；
  **不得把 `percent=25` 直接当作剩余 25%**。剩余绝对量若有则一并展示。
- **R003（异常与状态）**：需区分并展示以下状态：加载失败、未登录、CLI 缺失、未订阅、部分桶错误。
  **失败不得显示为 0**。
- **R004（刷新与退出）**：支持手动刷新；关闭浮窗 **不退出** 应用。
  【设计建议，MVP】托盘右键菜单提供“退出”作为 MVP 方案。
  > **v0.3 覆盖**：手动刷新仍支持，但“打开即刷新 / 点击查询”与“无自动刷新”已被
  > [UX011](interaction-improvements.md#ux011-后台轮询--跨重启持久状态--打开不查询--界面简化)
  > 覆盖为“全部打开路径零查询 + 启动后台一次 + 每 5 分钟轮询（含隐藏）”。
- **自动刷新频率与开机启动尚未确定**，本版不自行启用；第一版按需（手动 / 点击时）刷新为【设计建议】。
  > **v0.3 覆盖**：自动刷新频率已由 UX011 定为每 5 分钟后台轮询；开机启动仍不启用。

## 数据与数值规则

依据 [`../contracts.md`](../contracts.md)：

- 数值 `0` 与“字段缺失 / 未知”必须区别对待；缺失 / 非法一律**不补 0**，标为未知。
- **剩余百分比主公式**：`percent`（已用百分比）有效时，剩余百分比 = `clamp(100 - percent, 0, 100)`。
- **备用公式**：仅当 `used >= 0` 且 `total > 0` 且两者均为有限数（finite）时，
  剩余百分比 = `clamp((total - used) / total * 100, 0, 100)`。
- **`total = 0` 时百分比为未知**，不计算、不显示 0。
- 计算越界（被 clamp 截断）时需给出提示，说明原始数据异常。
- 剩余绝对量：仅在 `used >= 0` 且 `total` 有效且 `total - used` 有意义时计算
  `max(total - used, 0)`（`total = 0` 时未知）。
- 桶级 `error` 优先视为该桶错误，**不得当作“未订阅”**。
- 三个时间必须区分：`reset_at`（服务端重置时间）、`updated_at`（服务端数据更新时间，可能缺失）、
  `fetched_at`（本地本次查询时间）。
- 不在磁盘持久化敏感 `viewer` 身份标识；无跨账号的持久化缓存（数据仅存在于进程内存）。
  打开 / 刷新时的内存清空边界见 [`implemented-behavior.md`](implemented-behavior.md) 第 5、11 节。
  > **v0.3 覆盖**：“无跨重启本地额度持久化 / 数据仅存进程内存”已被
  > [UX011](interaction-improvements.md#ux011-后台轮询--跨重启持久状态--打开不查询--界面简化)
  > 覆盖为**跨重启本地快照**（DPAPI 加密、原子写入、仅存不可逆 scope 指纹，
  > **仍不持久化凭据与原始身份 ID**）。数据与数值规则本身不变。

## 异常与边界情况

| 情况 | 期望表现 |
| --- | --- |
| 加载中 | 明确的加载态，不显示 0 或旧账号数据 |
| 未登录 | 提示未登录，引导先完成 ArkCLI 登录；不显示 0 |
| CLI 不存在 | 提示缺少 ArkCLI，不崩溃、不显示 0 |
| 未订阅 | 明确“当前身份未订阅”，区别于查询失败 |
| 部分桶错误 | 展示可用桶数据，出错桶单独标注错误，不倒成 0 |
| 字段缺失（如 Coding Plan 无 used/total） | 只展示可得字段（如剩余百分比），缺失项标注未知；不补 0 |
| 字段越界（`percent` 不在 0–100） | 剩余百分比按 `clamp` 到 0–100，并提示原始数据异常 |
| `total=0` | 百分比与剩余量均标“未知”，不显示 0 |
| `updated_at` 缺失 | 正常展示数据与本地 `fetched_at`，区分本地查询时间与服务端更新时间 |
| 数字为 0 | 与缺失区分，正常显示 0 |
