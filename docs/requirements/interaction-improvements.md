### UX011 后台轮询 + 跨重启持久状态 + 打开不查询 + 界面简化

- 关联需求：R001、R002、R003、R004（交互细化，不改数据范围）。

#### A. 查询与轮询（打开零查询）

- **全部打开路径零查询**：启动（首启 / `--show` / 第二实例唤起）、托盘左键打开、
  右键“查看额度”、IPC 唤起，**只显示已有状态，不触发查询**。
  （覆盖 v0.2“打开即刷新”。）
- **默认启动后台一次，此后每 5 分钟**：应用启动后在后台立即查询一次，随后按
  **5 分钟**间隔定时轮询；**浮窗隐藏时也继续轮询**。
- **single-flight（单飞）**：启动查询、定时轮询、手动刷新共享**同一在途请求**；
  在途请求**不排队**，新的触发若已有请求在途则被合并 / 忽略，不并发、不堆叠。
- **手动刷新后更新**：手动刷新**等新结果返回后再更新展示**，而不是先切到“刷新中”。

#### B. 等待期间与终态（无过程态）

- **等待期间不变更**：请求在途时**不变更数据、标题、按钮、滚动、焦点**，
  **不显示任何过程提示**（无“正在查询 / 确认身份 / 刷新中 / 较慢仍在进行 / 取消”）。
  （覆盖 v0.2 UX003 的阶段 / 慢响应 / 取消 / 刷新中指示。）
- **成功终态一次提交**：成功时**一次性**提交新数据与时间。
- **相同数据避免不必要控件重建**：新结果与当前展示**语义相同**时，不重建卡片
  控件（避免闪烁 / 焦点丢失）。
- **后台失败短提示**：后台轮询失败时给出**简短提示**，并**保留上次成功数据及其
  原“最后更新时间”**（不伪认最新、不显示 0）。

#### C. 首次与空态

- **首次空态固定“暂无数据”**：无缓存且尚无结果时显示固定空态**“暂无数据”**，
  **不假造 0**。

#### D. 界面简化（保留 / 移除清单）

- **保留**：套餐名称；各周期**剩余额度 / 进度条**；**必要的**重置时间；
  **简短的最后更新时间**；**刷新**与**关闭**。
- **移除**：风险汇总 / 紧张周期 / 最低周期重复展示；冗余身份横幅；
  首启长 banner；及上述过程态提示。
  （覆盖 v0.2 UX006 突出最紧张周期、UX003 刷新态、UX010 持久首启 banner 的展示部分。）

#### E. 持久状态（工程落点）

- **跨重启本地快照**：以本地快照实现“持久状态”（工程选择满足需求，非用户指定实现）。
- **隔离**：复用现有 **state dir**（`ARK_LEFT_STATE_DIR` / `%LOCALAPPDATA%\ark_left`）
  支持测试隔离。
- **加密**：Windows **用户 DPAPI** 加密（`CryptProtectData` CurrentUser）。
- **原子写入**：临时文件 + 原子替换；**写入失败保留旧有效文件，不降级覆盖**。
- **隐私**：**不保存凭据与原始身份 ID**，只保存**作用域不可逆指纹**（SHA256）。
- **缓存语义完整**：缓存必须保存展示所需的**完整语义**：
  - 订阅 `known` 状态（`subscribed` 已知 / 未知）；
  - 产品级、周期级错误状态；
  - 数值 `known` 标志（`percent` / `used` / `total` / 剩余量的已知性）；
  - 时间（`fetched_at`、`updated_at`）。
- **不从非法日期推“现在”**：时间缺失 / 非法时**不得**回退为 `DateTime.Now` 假装新鲜。
- **损坏拒绝**：格式版本不符 / 结构损坏 / DPAPI 解不开 → **拒绝**，按无缓存处理。
- **只持久化成功类**：仅当 scope 判定 `Same` 时，持久化**有效成功 / 部分成功 /
  NoSubscription** 三种结果；**未知 scope 不写缓存**。

#### F. 身份与缓存的清 / 留规则

- **加载快照作为“上次历史”展示**，直到后台确认。
- **普通认证 / 网络失败**：**保持历史及原时间**，不得伪认最新。
- **立即清旧内存 / 磁盘**的情形（**可在身份确认阶段清**，这是唯一安全例外，
  **不显示过程态**）：
  - 明确 `NotLoggedIn`；
  - 认证**确定新 scope**（与已确认 scope 不同）；
  - usage `Mismatch`。
- **成功新身份结果再替换**展示与缓存。
- **Unknown 不证明不同身份**：可**保留历史**，但**不得把新的 Unknown 结果覆盖或
  持久化已有确认数据**；**无历史时** Unknown 显示**受限的当前结果**且**不缓存**。

## UX001 托盘左键开关与失焦事件竞态

- 关联需求：R001、R004
- 已观察：
  - `TrayApp.cs` `OnTrayClick`：左键时 `_form.Visible` 为真则 `HidePanel()`，否则
    `ShowPanel()` 后 `StartRefresh()`。
  - `PopupForm.WndProc` 监听 `WM_ACTIVATE`（`0x0006`）；`WA_INACTIVE` 且非抑制、
    非托盘菜单时，在打开约 250ms 宽限后 `HidePanel()`；`OnDeactivate` 兜底。
  - `ShowPanel` 期间 `_suppressHide=true`，托盘菜单打开期间 `TrayMenuOpen=true` 抑制隐藏。
- 潜在风险（**竞态，未人工复现**）：
  - 用户点击托盘图标会使浮窗失去焦点，可能产生 `WM_ACTIVATE(WA_INACTIVE)`；
    该隐藏路径与 `OnTrayClick` 的“可见性切换”判断存在**时序竞态**：
    若失焦隐藏先执行，`OnTrayClick` 会把本意“收起”的动作变成“重新弹出”；反之可能闪烁。
  - 未做人工复现，登记为潜在风险而非已发生缺陷。
- 方案（授权方向）：
  - 引入统一的切换入口与明确的抑制窗口：托盘点击处理期间临时抑制失焦隐藏，
    并以“本次点击开始时记录的可见性”作为切换依据，避免同一次用户动作被两条路径重复处理。
  - 保留打开后点击其他窗口按预期收起的现有行为。
- 验收场景：
  - 连续快速左键点击托盘若干次，窗口“每次点击切换一次”，奇偶与点击次数一致，无明显闪烁。
  - 打开后点击桌面其他窗口，浮窗仍按约 250ms 宽限收起。
  - 打开托盘右键菜单不会误触收起。
- 代码范围：`src/TrayApp.cs`（`OnTrayClick` / `WndProc` / `ShowPanel` / `HidePanel` / 抑制标志）。
- 依赖：UX009（临时面板定位）。

## UX003 刷新保留同身份快照 / 固定尺寸 / 阶段提示 / 慢响应 / 取消或重试

- 关联需求：R002、R003、R004
- 已观察：
  - `TrayApp.StartRefresh`：入口 `if (_exiting || _querying) return;` 防重入；
    仅当 `_form.Visible` 时 `SetLoading()`（清空 `_last` 并显示“正在查询…”）。
  - `_last` 为单份内存快照，未与任何身份绑定；窗口高度由 `DesiredHeight` 随内容变化。
  - 无阶段提示、无取消按钮、无重试按钮；每命令超时 30s，`auth`+`usage` 顺序执行，
    最坏总耗时可能超过 60s（见 `implemented-behavior.md` 第 8 节）。
- 潜在风险：
  - 刷新时旧的成功数据被清空，慢响应期间用户看不到上次结果。
  - 加载态与结果态高度不同，面板会跳动。
  - 长耗时无阶段反馈，用户不知卡在哪一步、也无法取消或重试。
  - 若无身份绑定，切换到另一账号后可能短暂复用旧身份的内存快照。
- 方案（授权方向）：
  - 刷新时**保留同身份上一次成功快照**（不再无条件清空），以“刷新中”指示叠加在旧数据上。
  - **固定面板尺寸**：加载 / 结果切换不改变窗口外框尺寸，内容超出时在内容区滚动。
  - **阶段提示**：区分“正在检查登录状态 / 正在查询额度 / 正在解析”。
  - **慢响应提示**：超过阈值后提示“仍在查询”，并给出**取消**动作；失败或取消后提供**重试**。
  - **身份隔离**：快照必须与身份 scope 绑定；身份未知或变化时不得复用（与 UX008 配合）。
- 验收场景：
  - 刷新进行中，面板仍显示上次成功数据并有“刷新中”指示。
  - 加载态与结果态的面板外框尺寸一致，不跳动。
  - 响应超过阈值后出现“仍在查询”提示且可取消；取消 / 失败后可重试。
  - 身份变化后旧身份快照被清空，不跨身份复用。
- 代码范围：`src/TrayApp.cs`（`StartRefresh` / `SetLoading` / `Render` / `PopupForm` 尺寸与内容区）。
- 依赖：UX008（身份指纹）。

## UX006 信息层级：突出最紧张周期与低额度提示

- 关联需求：R002
- 已观察：
  - `BuildPeriodRows` 对每个周期同等展示“剩余 N%”（14pt 粗体）+ 进度条；
    `DisplayNames.Number` 用 `"0.##"` 格式化；无低额度配色阈值。
  - 未知显示“剩余未知”，桶错误显示“获取失败”，`QuotaBar.Value<0` 绘制空条（不暗示 0）。
- 潜在风险：
  - 多产品 / 多周期时所有百分比同权重，用户难以一眼看出**最紧张**的周期。
  - 对小额剩余（如 0.4%）显示不明确；无低额度视觉提示，容易被忽略。
- 方案（授权方向）：
  - **突出最紧张周期**：在可比较的周期中仅选**剩余百分比最小**者突出显示。
    比较**仅按剩余百分比**，**不得把不同周期 / 不同产品的额度数值相加**后再比较。
  - **显示精度**：百分比用整数或一位小数；当 `0 < 剩余值 < 1` 时显示 **“<1%”**（不显示 0）。
  - **低额度提示**：采用**文字 + 颜色**双重提示；颜色之外必须有文字，避免仅靠颜色传达。
  - 未知 / 失败维持明确文案，不显示 0。
- 验收场景：
  - 给定多产品多周期数据，只有剩余百分比最小的周期被突出。
  - 比较过程不出现额度数值相加。
  - 剩余 0.4% 显示为“<1%”。
  - 低额度同时出现文字与颜色提示。
  - 未知 / 失败不显示为 0。
- 代码范围：`src/TrayApp.cs`（`BuildCards` / `BuildPeriodRows` 选中与渲染）、
  `src/Models.cs`（`DisplayNames` 格式化）。
- 依赖：UX003（固定尺寸下的突出展示）。

## UX007 重置倒计时与时间口径区分

- 关联需求：R002、R004
- 已观察：
  - 每个周期有 `reset_at` 时显示“重置 yyyy-MM-dd HH:mm”。
  - 产品卡在 `HasUpdated` 时显示“服务端数据更新 …”；底部显示“查询时间 yyyy-MM-dd HH:mm:ss”。
  - 三个时间语义（`reset_at` / `updated_at` / `fetched_at`）在解析层已区分；
    **界面无倒计时，也无计时器**（`TrayApp` 中无 Timer，唯一 Timer 在 `RunSmokeTest`）。
- 潜在风险：
  - 只给绝对重置时间，用户无法直观感知“还剩多久”。
  - “本地查询新鲜度”（多久前查询）与“服务端更新时间”易被混淆。
- 方案（授权方向）：
  - 在重置绝对时间旁增加**相对倒计时**作为辅助，**不替代**绝对时间。
  - 明确区分并分别标注：
    - **本地查询新鲜度**：基于 `fetched_at` 的“x 分钟前查询”。
    - **服务端更新时间**：基于 `updated_at`，来源不同不混称。
  - 计时器**仅重绘倒计时文本**，**绝不触发任何查询 / 网络 / 子进程**；
    浮窗隐藏或退出时停止计时器。
- 验收场景：
  - 界面同时显示重置绝对时间与倒计时。
  - 本地新鲜度与服务端更新时间分别标注，不混淆。
  - 观察计时器运行时只更新文本；无新 CLI 子进程、无网络请求。
  - 隐藏浮窗后计时器停止。
- 代码范围：`src/TrayApp.cs`（新增 WinForms `Timer`；`BuildPeriodRows` / `BuildProductCard` / 底部时间）。
- 依赖：UX003。

## UX008 隐私安全身份提示与内存 scope 指纹

- 关联需求：R002、R003
- 已观察：
  - 应用不提取 / 不展示 `usage plan` 的 `viewer` 身份对象。
  - 无身份提示，无 scope 指纹；`TryReadLoggedIn` 仅读取 `logged_in` 布尔。
  - 数据仅存于进程内存，无磁盘缓存（`implemented-behavior.md` 第 11 节）。
- 潜在风险：
  - 用户不知道当前展示的是哪个身份的额度。
  - 若引入跨刷新复用，缺少身份绑定可能导致跨账号误复用内存快照。
  - 若误用账号 ID / 名称作为提示，可能泄露敏感身份信息。
- 方案（授权方向）：
  - 增加**身份提示**：优先使用 `profile.name`，或与产品相关的友好标签
    （如“Agent Plan 个人版”）；**不显示账号 ID、不显示 key、不使用用户敏感姓名**。
  - 在**内存中**基于账号 scope 派生一个**不可逆指纹**，仅用于缓存比对（判断是否同一身份）；
    **不写盘、不展示**。
  - `auth` 状态未知（格式错误 / 失败 / 超时等无法确认身份）时**清空内存快照**，
    禁止复用到下一次。
- 验收场景：
  - 身份提示不含账号 ID / key / 用户敏感姓名。
  - 检查文件系统确认无指纹 / 身份落盘（本地扫描不产生新持久化文件）。
  - `auth` 未知后旧快照被清空。
  - 身份变化后不复用旧数据。
- 代码范围：`src/Identity.cs`（真实 schema 解析 / 内存 scope / 友好提示）、
  `src/QuotaCli.cs`（`ScopeValidation` 交叉校验）、`src/ViewState.cs`（缓存复用门控）、
  `src/TrayApp.cs`（身份提示渲染）。
- 实现事实（已由主代理真实脱敏查询确认，见 [`../contracts.md`](../contracts.md)）：
  真实 `auth` 为 `active_profile{name,type,owner_trn,region,project}`，
  真实 `usage viewer.profile` 为**字符串**（非嵌套 `viewer.profile.name`）。
  scope 解析 `owner_trn` 为 `trn:iam::<account>:root | :user/<id>`，不支持格式 => unknown。
  字段名此前“尚未逐项确认”的疑问**已关闭**，无需回退。属技术核对，不改业务含义。
